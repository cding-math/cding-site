## Decisions to preserve

- English: Changying Ding. Chinese: 丁长缨, using Zhuque Fangsong v0.212.
  Desktop reveals on hover/keyboard focus; mobile/touch displays plain text
  persistently. No visible hint or theme/grid toolbar belongs in production.
- The shared 72 px heading comprises three 24 px upright Chinese cells; English
  is centered against the full column. The intro starts 24 px below it. Preserve
  the 8 px spacing scale and page-wide alignments in the design specification.
- Primary text fonts are a 38,136-byte Inter core and a 2,572-byte Chinese subset.
  Broad Latin/full Inter remain on demand, through disjoint Unicode ranges.
  Never replace the chosen glyphs with a visually similar face.
- Local body fallback metrics reduce reflow while Inter loads. They are tuned
  to current text and dimensions; content/typography changes need retesting.
- KaTeX 0.19.1 HTML/MathML is generated by a maintainer script and committed.
  New expressions must be added to the cache. Cloudflare runs Hugo only.
- Production CSS/JS/font resources use content hashes and immutable caching.
  HTML revalidates. Cloudflare Browser Cache TTL is Respect Existing Headers.
  Do not disable bot/security protections to improve benchmark scores.
- `static/css/style.css`, `static/js/site.js` and legacy vendor paths remain for
  old cached pages. Edit `assets/` and layouts for current behavior.

## Verification and limits

Final live mobile Slow 4G: first content 0.611 s, largest content 1.340 s,
CLS 0.000287 (formerly 0.077907). Warm load: 0.246 s, zero CLS and zero font
transfers. Chinese finished before first paint in every cold test. The final
matrix, cache evidence and screenshots are committed in the audit directory.

These are Chromium lab measurements on macOS with mobile viewport/CPU/network
emulation, not physical iOS/Android or field data. Very slow first visits can
show English fallback letterforms; small inline movement remains. The portrait
is the remaining Slow 3G bottleneck (LCP 4.578 s). No extra optimization is pending
or pre-authorized; re-evaluate only when a future task requires it.

## Next-change workflow

1. Check `git status` and read the relevant canonical document above.
2. Edit production source, not generated `public/` or historical demo copies.
3. For new math, regenerate/check the cache. For fonts, follow the reproducible
   subset instructions and preserve license/fidelity checks.
4. Use Hugo 0.157.0 for the release build, then run the README validation commands.
   The installed Homebrew Hugo was 0.163.3 during this session; do not assume
   `hugo` on PATH matches Cloudflare. The temporary pinned binary used today is
   disposable and is not a project dependency.
5. Inspect regenerated `public/` (tracked), review the diff, and stage only
   intended files. Deployment requires the current task's authorization.
6. After an authorized push, verify its Cloudflare check and the actual custom
   domain; a successful local build alone is not deployment verification.

Rollback uses reviewed Git reverts of the relevant implementation commits,
followed by an authorized push. Do not reset shared history. For a full rollback
of today's feature, review `d3d0aed`, `abe00ec` and `d9a9595` together, in reverse
order; reverting only one may leave dependent changes.
